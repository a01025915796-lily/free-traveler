## 1. 원칙

- Screen은 `SCREEN_ROUTE_CONTRACT.json`의 5개뿐이며 Screen마다 Page Owner Task가 정확히 하나다. Page Owner만 해당 `page.tsx`를 소유한다.
- Page Owner는 같은 Screen의 모든 Component Task와 필요한 Data·DB Access Task에 의존한다.
- 여행지·안전정보·대표 콘텐츠는 `src/data` 정적 데이터, 즐겨찾기는 `localStorage`, 알림은 Toast·화면 상태다.
- DB 테이블은 `profiles`, `mate_posts`, `mate_applications`, `user_blocks`, `reports`, `app_settings` 6개뿐이다. 자체 Route Handler·API Route·Server Action은 없다.
- 항공·숙소 입력값은 서버·DB·URL·쿠키·`localStorage`·로그·분석으로 보내지 않는다.
- Playwright는 Chromium Smoke 3개 Task이며 핵심 흐름 FLOW-01~07(7개)을 나눠 맡는다(DEC-016). 자동 Merge·EC2·AWS Task는 없다. Production 배포·Merge는 사용자가 한다.
- Seq는 의존 관계 순서다. 의존 Task는 항상 더 앞 Seq에 있다.
