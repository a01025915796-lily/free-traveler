## 1. 열 정의

| 열 | 값 |
|---|---|
| Requirement | 기준 SRS 요구사항 ID |
| Implementation Status | 범위 분류: IMPLEMENT(구현 대상) / EXCLUDED(제외) |
| Screen | 배치 디자인 Screen. 공통 Layout은 5개 Screen 공통, 기술 Route는 디자인 Screen이 아닌 경로, 비UI는 화면 요소가 없는 데이터·보안·운영 요구사항 |
| Route | 해당 Screen의 Route |
| Page Entry | 해당 Route의 진입 파일 |
| Task | 이 요구사항을 참조하는 구현 Task와 테스트·확인 Task ID 전부(Seq 순서, 쉼표 구분). 출처: `TASKS/00_TASK_LIST.md`·`TASKS/TASK_MANIFEST.csv`. EXCLUDED는 Task를 만들지 않으므로 `EXCLUDED` |
| Test | 실제 확인 방법과 담당 Task: Unit(Vitest 단위 테스트) · RLS(Supabase 권한 통합 테스트) · Playwright(Chromium Smoke) · Manual(수동 확인·출시 판정). `— 06:` 뒤는 `06_SRS_UIUX_REVISED.md` §8 검증 ID. EXCLUDED는 `없음 (EXCLUDED)` |
| Status | 진행 상태: NOT_STARTED(미착수) → IN_PROGRESS(구현 중) → IMPLEMENTED(구현 완료, 검증 전) → VERIFIED(Test 통과) / EXCLUDED(제외) |

Status는 Test 결과가 있어야 VERIFIED로 바꾼다. 코드만 작성한 상태는 IMPLEMENTED다.
